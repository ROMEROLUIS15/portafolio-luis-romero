Case Study Cronix
250+ Real appointments managed
1.6K+ Tests written
59 RLS policies / 32 tables
9 Edge Functions (Deno)
The Problem
  • Appointment-based businesses lose clients because they can't respond 24/7 — phone goes unanswered, WhatsApp unread.
  • Existing solutions are generic chatbots that hallucinate, confirm wrong appointments, or act on the wrong client's data.
  • The core risk: connecting an LLM to a real database without deterministic guardrails causes irreversible errors.
The Solution
  • Custom AI orchestration engine — no LangChain, no framework — giving full control over every step of the flow.
  • Multi-tenant SaaS: each business gets isolated data (PostgreSQL RLS), its own agent config and its own metrics dashboard.
  • Automated reminders via pg_cron — zero manual intervention required once onboarded.
Anti-Hallucination Architecture — 6 Layers
L1
Fast Paths
Known queries resolved directly from DB — LLM never called, zero hallucination surface.
L2
Identity Verification
Client identity confirmed before any read or write. Prevents acting on the wrong client's data.
L3
Restricted Tool Calling
Function calling constrained to declared args only — the LLM cannot invent parameters.
L4
2-Turn Confirmation Gate
Every destructive mutation (book, reschedule, cancel) requires explicit user confirmation in a second turn.
L5
Response Guardrail
Output validated against known-safe patterns before delivery. Blocks off-topic or fabricated responses.
L6
Observability & Regression CI
LLM-as-judge (DeepEval) on versioned golden datasets in CI. Multi-tenant tracing → LangSmith. p50/p95 per business.
Key Technical Decisions
  • No framework for orchestration — full control over tool execution order, retries and fallback logic without black-box behavior.
  • PostgreSQL RLS over application-level isolation — 59 policies across 32 tables, validated with 138 pgTAP assertions. Data leaks between tenants are impossible at the DB level.
  • WebAuthn/Passkeys over passwords — phishing-resistant auth with no shared secrets to leak.
  • QStash for async payment fulfillment — idempotent processing with guaranteed at-least-once delivery, no payment lost on server crash.
  • Deno Edge Functions — global low-latency for the AI agent with no cold start on Supabase infra.
